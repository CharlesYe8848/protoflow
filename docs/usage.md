# 使用说明与常见问题

**项目保存在哪里？**

默认保存在工具启动时的工作目录。创建时可以告诉 AI 希望保存的位置；不确定时，让它返回项目文件夹路径。项目是普通本地文件夹，可以自行备份和移动。

**需要额外配置模型 API Key 吗？**

ProtoFlow 本身不需要。生成和修改内容使用你已经在 AI 助手中配置的模型；模型的使用条件和费用由相应服务决定。

**为什么第一次截图需要下载东西？**

截图需要 Chrome。ProtoFlow 会优先使用本机已有的 Chrome，找不到时自动下载，因此首次截图可能需要等待。下载失败时，先检查网络，或安装 Chrome 后重试。

**原型更新后，PRD 的截图也会自动更新吗？**

原型预览刷新后会显示最新内容；已保存的 PRD 保留原版本。对于通过 ProtoFlow 截图流程建立关联的文档，检查时会提示原型变化，你再决定何时更新文档。

**支持哪些系统？**

当前预览版已在 macOS 本地验证，并通过 macOS / Linux、Node.js 22.12 和 24 的自动安装、截图与完整测试。Windows 完整使用体验尚未完成验证。

**可以打开别人发来的项目吗？**

请只打开可信来源的项目。项目可能包含会执行的代码，详细边界见 [安全说明](../SECURITY.md)。

遇到问题可在 [Issues](https://github.com/CharlesYe8848/protoflow/issues) 反馈，附上操作系统、Node.js 版本、使用的 AI 助手和复现步骤。


## 安装与预览

使用 nvm 管理 Node.js 时，进入 ProtoFlow 目录后，可以先运行 `nvm install && nvm use`，再运行 `npm ci`。

连接 AI 助手后，重新打开会话并确认 ProtoFlow 工具已加载。

原型画布支持左侧切换页面、滚轮平移、Ctrl/Cmd + 滚轮缩放。悬停画板，点击「标注」即可查看说明，点击标注中的元素名称可以定位。

## 体验内置示例

运行 `npm run demo`，打开输出的 `canvas` 和 `prd` 链接。示例使用虚构数据，不会发起真实支付。
示例副本位于系统临时目录；如需长期保留，请将输出的 `projectDir` 文件夹复制到自己的工作目录。
完整步骤见 [结账流程示例](../examples/README.md)。

## 分享与发布

本地预览链接只在自己的电脑上有效。给同事查看时，可以通过画布或文档右上角的「分享」导出文件。
文档支持导出 Word（`.docx`）、单页 HTML 和 Markdown 压缩包。Word 包含当前版本的可编辑正文、表格、列表及本地 PNG/JPEG/GIF/BMP 图片；Mermaid 保留为代码，无法嵌入的图片会注明原始地址。画布仍支持项目 HTML 和单页 HTML。
如果要发布到钉钉等平台，需要先为 AI 助手配置相应的平台工具和授权。

## 技能与工具连接检查

场景入口在 `skills/protoflow/SKILL.md`；安装技能后仍需要连接 MCP 或提供本地 CLI。
以下检查分开进行，命令成功不代表助手当前会话已经加载技能：

1. **技能发现**：重新打开助手会话，在可用技能列表中确认 `protoflow`。仅把仓库下载到磁盘不等于安装技能。
2. **运行时**：在仓库根目录执行 `npm run selfcheck`，验证 MCP/CLI 入口可启动。
3. **指南读取**：执行 `node bin/protoflow-cli.js get_guide '{"topic":"workflow"}'`，应返回场景指南。
4. **MCP 连接**：在助手中显式要求“用 ProtoFlow 读取工作流指南”，确认实际调用成功。CLI 自检不能替代这一步。
5. **隐式命中**：在另一个新会话中说“做一个可点击的报销审批原型”，观察是否主动选择 ProtoFlow；这个验证会创建原型，请使用临时工作目录。

没有 MCP 时，可以告诉助手仓库的绝对路径，通过 `node /实际仓库路径/bin/protoflow-cli.js` 使用相同工具。
CLI 的第二个参数是 JSON，参数定义位于 `mcp/tools.js` 的对应 schema。不要假定安装了 Skill 就存在全局 `protoflow` 命令。

已有项目传 `projectId`（项目文件夹名）和 `dir`（父目录）；相对路径容易受助手启动位置影响，推荐绝对父目录。
项目找不到时先核对位置，不重新创建同名项目。更新技能需要重新复制已检查的内容并重新打开会话；本版没有自动更新器。

用于对比改造前后表现的场景和记录方式见[技能场景评测](skill-evaluation.md)。
