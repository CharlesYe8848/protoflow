# ProtoFlow 技能场景评测

本文件是人工或模型行为评测用例，不是已经测得的命中率。格式校验、CLI 自检、工具测试通过，
只能证明入口可读取和操作契约有效，不能证明助手会主动选择技能。

## 对照方法

- 同一模型、相同设置、相同其他技能和工具，使用独立新会话；记录模型版本、技能版本和日期。
- 只评估“技能发现”的 A/B：运行时和指南保持一致，A 不安装 ProtoFlow 技能，B 安装技能。
  若还要评估指南改造，另设实验，不把多个变化混在一个命中率里。
- 给执行者只提供“用户请求”和“上下文”，不提供期望路径、禁做事项或本文件；评分者才读取完整表。
- 真实触发评测不要显式点名技能或预先加载它。显式指定只用于对应测试项。
- 使用隔离工作目录。已有项目用 `examples/checkout` 的副本，并为各组提供同样副本；
  未知路径、多项目和草稿等场景按表设置。渠道场景使用模拟平台，不向真实平台发布。
- 每个场景建议至少运行三次，保留逐次结果，不只保留最好的一次。
- 下表为设计样例；后续加入真实发生过“需要提醒”的脱敏请求，保留一组未用于修改技能的留出用例。

## 评分记录

逐次记录：场景 ID、实验组、模型/设置、实际首次入口、所读指南、工具调用、产物变化、
额外询问、是否扩大范围、完成情况、耗时、失败原因及会话记录位置。

分别报告：

- 应命中场景的主动命中率，单独列出显式指定和隐式请求。
- 排除场景的误触发率；缺少运行时但正确识别应使用 ProtoFlow，不算发现失败。
- 已有项目复用率、正确工作流比例、交付完成率。
- 无关写入/定版/发布次数、不必要追问次数。

不要把工具执行失败归为发现失败，也不要把提到 ProtoFlow 名称但未使用工具算成交付成功。
边界场景允许合理澄清，不要求机械匹配固定调用序列。
