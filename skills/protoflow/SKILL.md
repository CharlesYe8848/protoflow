# ProtoFlow

完成用户本次原型或交付任务。先识别项目和交付范围，再使用运行时提供的场景指南；
只做原型时不自动生成 PRD，只检查时不自动修复或发布。

## 选择入口

- 新建可点击、供演示或评审的产品原型：使用 ProtoFlow；用户不必提到工具名称。
- 已有 ProtoFlow 项目：沿用项目、页面、画板和文档，不重复建项目，不重开需求访谈。
- “做个后台页面”“写个 PRD”没有原型交付或已有项目上下文：先结合代码库和对话判断；
  仍不明确时问一个关于交付物的问题，不因出现“页面”或“PRD”就创建项目。
- 明确指定 Figma、其他工具或生产应用代码：沿用指定工具。只有另外要求 ProtoFlow
  交付或明确迁移时才进入；不假定外部设计文件可直接导入。
- 用户显式指定 ProtoFlow 时，可处理其支持的独立文档等操作，不强制先制作原型。

## 连接工具并读取规范

优先使用可用的 ProtoFlow MCP。首次进入调用 `get_guide({"topic":"workflow"})`，
按其场景表选择当前步骤。其他主题和文档类型规范按需获取，不一次性读取全部指南。

没有 MCP 时，使用已安装的 `protoflow` CLI，或已知仓库中的
`node /实际仓库路径/bin/protoflow-cli.js`。子命令与 MCP 工具同名，第二个参数为 JSON：

```bash
protoflow get_guide '{"topic":"workflow"}'
protoflow --help
```

不要从技能安装目录推算运行时路径；技能可以单独安装。路径未知且 CLI 不可用时，
说明缺少连接并询问安装位置，不能声称已经生成预览或完成构建。
参数以 MCP schema 为准；CLI 参数不明时查看运行时 `mcp/tools.js` 中对应 schema，勿猜参数。

## 定位已有项目

项目恢复的具体步骤（`project.json`/`projectId`/`dir` 关系、`list_projects` 消歧、
项目找不到时的处理）已在 `get_guide({"topic":"workflow"})` 开头给出，按其执行，
不在本文件重复维护一份。

## 完成交付

按工作流完成标准收尾，给出所需预览、导出文件或检查结果。
编译通过不等于交互验证通过；制作或修改原型后，用可用浏览器检查相关界面与交互，
无法检查时明确尚未验证的部分。本地预览链接只供本机访问。
文档或渠道落后时说明影响，按本次范围决定是否更新，不为消除提示擅自定版或发布。
